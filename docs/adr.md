## 2. D1. Создание функций

### 2.1 Решение

Фабрика это класс TFunctionFactory в src/factory.h. Внутри у нее std::map, где ключ это имя функции ("ident", "power" и т.д.), а значение это лямбда, которая получает вектор параметров и возвращает std::shared_ptr<TFunction>.

Методы фабрики:

```cpp
std::shared_ptr<TFunction> Create(const std::string& type);
std::shared_ptr<TFunction> Create(const std::string& type, double param);
std::shared_ptr<TFunction> Create(const std::string& type, std::vector<double> params);
void Register(const std::string& type, Creator creator);
```

Create с одним числом и Create без параметров просто кладут параметры в вектор и вызывают третий Create. Вызов `Create("polynomial", {7, 0, 3, 15})` попадает в версию с вектором.

Параметры: у ident и exp параметров нет, у const это значение константы, у power показатель степени, у polynomial коэффициенты начиная со свободного члена.

Все функции регистрируются в конструкторе фабрики в src/factory.cpp, там по одной строчке на функцию:

```cpp
Register("power", [](std::vector<double> p) { return std::make_shared<TPower>(p); });
```

Чтобы добавить sin, надо написать класс TSin в новых файлах src/sin.h и src/sin.cpp, добавить одну строчку Register в конструктор фабрики и добавить файл в CMakeLists.txt. Файлы function.h/.cpp, functions.h/.cpp и старые тесты при этом не меняются.

Если имя неизвестное, Create бросает std::invalid_argument. Если параметров неправильное количество (например у power нет показателя или у полинома пустой список), исключение std::invalid_argument бросает конструктор функции, потому что только сама функция знает, сколько ей нужно параметров.

### 2.2 Альтернативы

Альтернатива 1: цепочка if по имени прямо в Create, без map и Register. Не выбрал: для каждой новой функции придется править сам Create. Пришлось бы менять src/factory.h и src/factory.cpp.

Альтернатива 2: саморегистрация, каждая функция регистрирует себя через глобальную переменную в своем файле. Не выбрал: фабрика должна стать глобальной, а порядок создания глобальных объектов в разных файлах не определен. Пришлось бы менять src/factory.h, src/factory.cpp и src/functions.cpp.

## 3. D2. Владение и время жизни

### 3.1 Решение

В TFunction три поля:

```cpp
std::function<double(double)> func;   // значение
std::function<double(double)> deriv;  // производная
std::string str;                      // для ToString
```

Производная нужна по пункту 1, поэтому я ее храню уже сейчас. В основных функциях она задается формулой (например для x^n это n*x^(n-1)), а в операторах считается по правилам: (f+g)' = f'+g', (f*g)' = f'g + fg', (f/g)' = (f'g - fg')/g^2. Метод GetDeriv я добавлю в пункте 3.

TPower, TExp и остальные это наследники TFunction, которые только заполняют эти три поля в конструкторе. Своих полей у них нет, поэтому если скопировать TPower в TFunction, ничего не потеряется. Виртуальных функций нет, так как вся логика лежит в std::function.

Фабрика возвращает std::shared_ptr<TFunction>, потому что в примере из задания указатели кладутся в вектор и копируются в цикле, а unique_ptr копировать нельзя. unique_ptr я нигде не использую.

Выражения хранятся по значению. Оператор + получает две TFunction по константной ссылке, копирует их в лямбду и возвращает новую TFunction:

```cpp
TFunction operator+(const TFunction& a, const TFunction& b) {
    TFunction res;
    res.func = [a, b](double x) { return a(x) + b(x); };
    res.deriv = [a, b](double x) { return a.deriv(x) + b.deriv(x); };
    res.str = "(" + a.ToString() + " + " + b.ToString() + ")";
    return res;
}
```

Так как a и b скопированы внутрь, выражение не зависит от исходных функций и работает, даже если указатель f уже удален.

Выражения можно копировать и присваивать, конструкторы копирования и присваивания делает компилятор. При копировании копируются все std::function вместе со всем, что в них лежит, то есть фактически все дерево выражения. `p = p + *f` работает нормально, потому что старое p сначала копируется в лямбду.

### 3.2 Альтернативы

Альтернатива 1: дерево узлов, где каждый узел владеет детьми через unique_ptr, а TFunction абстрактный класс. Не выбрал: абстрактный класс нельзя вернуть по значению, как в `auto p = *f + *g`, и для копирования нужен Clone в каждом классе. Пришлось бы менять src/function.h/.cpp и src/functions.h/.cpp.

Альтернатива 2: выражение хранит указатели на операнды, а операнды хранит пользователь. Не выбрал: в `(*f + *g) + *h` сумма f+g временная и удалится в конце строки. Пришлось бы менять src/function.h/.cpp.

Минусы моего варианта:
- при каждом копировании выражения копируется все дерево, так что длинное выражение из n операций строится примерно за n^2. Для этого задания выражения маленькие, так что это не страшно;
- строка ToString хранится в каждом узле целиком, у длинного выражения это много памяти;
- у TFunction деструктор не виртуальный, поэтому наследникам нельзя добавлять свои поля, но это держится только на договоренности.

## 4. D3. Идентификация типов и ошибки

### 4.1 Решение

Тип функции код нигде не проверяет. ToString просто возвращает поле str, которое заполнил конструктор основной функции или оператор. Тип выбирается только в фабрике по строке.

Строки у основных функций: "x", "5", "x^2", "exp(x)", полином как "7 + 3*x^2 + 15*x^3" (нули пропускаются). Числа превращаю в строку через std::ostringstream, поэтому 2 печатается как "2", а не "2.000000", как было бы с std::to_string.

Проверка допустимости операции происходит при выборе перегрузки оператора. Кроме нормального `operator+(const TFunction&, const TFunction&)` в src/function.h есть шаблоны для всех остальных типов:

```cpp
template <typename T,
          typename = std::enable_if_t<!std::is_base_of_v<TFunction, std::decay_t<T>>>>
TFunction operator+(const TFunction&, const T&) {
    throw std::logic_error("unsupported type in operator +");
}
```

и такой же с другим порядком аргументов. Так же для -, * и /. enable_if нужен, чтобы шаблон не подходил для TPower и других наследников, иначе для объекта TPower шаблон выбирался бы вместо нормального оператора. Поэтому `*f + "abc"` компилируется и бросает std::logic_error.

Числа тоже считаются неподдерживаемым типом, `*f + 2` бросает std::logic_error. Константу нужно создавать через фабрику: `Create("const", 2)`.

При вычислении исключений нет. Если делим на ноль или берем корень из отрицательного, получится inf или nan, и это просто возвращается.

### 4.2 Альтернативы

Альтернатива 1: шаблоны через `= delete`, тогда ошибку найдет компилятор. Не выбрал: в задании нужно исключение std::logic_error, а такой код просто не скомпилируется. Пришлось бы менять src/function.h.

Альтернатива 2: хранить в TFunction enum с типом функции и проверять его в операторе во время работы. Не выбрал: при добавлении sin пришлось бы дописывать enum. Пришлось бы менять src/function.h/.cpp и src/functions.cpp.

Минусы моего варианта:
- ошибку, которую мог бы найти компилятор, видно только при запуске, поэтому на каждый оператор нужен тест на исключение;
- `*f * 2` выглядит нормально, но бросает исключение, это неудобно;
- по объекту нельзя узнать, какая это функция, есть только строка ToString.
